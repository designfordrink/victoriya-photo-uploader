# Phase 1 — Domain, jobs, storage и manifest

**Связанные задачи:** IMP-006–IMP-011  
**Основа:** принятые Detailed Specification v0.1 и Implementation Plan v0.1  
**Реализация:** PR-02, отдельная ветка от `main`

## Что реализовано

- Pydantic-модели `PhotoJob`, `Asset`, `ProductIdentity`, `WatermarkResult`, `ProcessingResult`, источника и выходного файла, путей, ошибок и расхода.
- Явные перечисления статусов задания и watermark. Неизвестные поля отвергаются; confidence/probability ограничены диапазоном 0–1; timestamps должны содержать timezone.
- `JobStateMachine` проверяет допустимые переходы из спецификации, фиксирует историю переходов и не разрешает продолжать из финальных состояний.
- `JobRepository` хранит JSON-записи в локальной папке `Victoriya/jobs/`. Создание не перезаписывает существующую запись; обновление выполняется атомарной заменой.
- `StorageManager` создаёт `source/<job_id>/`, `source/<job_id>/work/`, `output/` и `reports/` внутри папки бренда/модели.
- `ManifestWriter` записывает JSON-манифест в `reports/<job_id>.json`; `MarkdownReportWriter` формирует человекочитаемый отчёт рядом.
- SHA-256, exact deduplication и копирование оригиналов без перезаписи. Одинаковый файл распознаётся по содержимому; другой файл с тем же именем вызывает явную ошибку.

## Важные гарантии

- Дубликат определяется только совпадением SHA-256. Похожие ракурсы автоматически не объединяются.
- Оригинал открывается только для чтения; его hash проверяется до и после копирования.
- Существующий файл с другим hash не заменяется.
- Все пути рабочих каталогов строятся через существующий `PathManager`; источники, рабочие файлы, результаты и отчёты разделены.
- В этой фазе нет Playwright, OpenRouter, Jev, Stability API и платных вызовов.
